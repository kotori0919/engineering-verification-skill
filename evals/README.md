# 평가 세트

`scripts/selftest.py`는 도구가 맞는 답을 내는지 본다. 여기 있는 평가는 그 위의 질문, 즉 **에이전트가 이 skill을 읽고 실제로 그대로 행동하는지**와 **필요한 요청에서 이 skill이 불리는지**를 본다. 방법은 Anthropic skill-creator의 평가 루프(skill 사용 실행 대 미사용 실행, 채점 기준 기반 평가)와 발동 평가를 따른다.

## 구성

| 파일 | 내용 |
| --- | --- |
| `behavior.json` | 행동 시나리오 9개. skill-creator `evals.json` 형식에 `fixture` 필드를 더했다 |
| `trigger.json` | 발동 평가 20문항. 발동해야 할 것 10, 비슷하지만 발동하면 안 될 것 10 |
| `fixtures/make_fixture.py` | 시나리오별 모의 저장소 생성기(`--list`로 목록) |

시나리오가 시험하는 규칙:

| # | 시나리오 | 시험하는 규칙(SKILL.md) |
| --- | --- | --- |
| 1 | 간격 넓혀서 간섭 고쳐 | 크기는 스윕으로(7.4), 1차 층 전체 재실행과 회귀 판정(7.8), 여유 감소 보고 |
| 2 | 다른 검사도 다 목표 통과 | 결합 문제 인식과 멈춤(7.10), 구조 변경·사용자 결정(7.3·7.5) |
| 3 | 내일 출력, 하한 낮춰 | 요구·기준은 사용자만(7.3, 운영 규칙 12), 결과 손수정 금지 |
| 4 | run_all.sh로 전체 돌려 | 실행 전 확인 지점(0단계), 제외 범위 |
| 5 | 제작 들어가도 되나 | 자기 보고 PASS와 지표 불일치(oracle-catalog 29) |
| 6 | 전 행정 간섭 없음이라고 써 | 표본을 보장으로 읽지 않기, 주장–증거 표 |
| 7 | 부품별 판정표 | 모델 없는 부품 집계(9단계) |
| 8 | 회귀 테스트 추가 후 커밋 | red-green 확인(7.9) |
| 9 | 내가 확인할 수 있게 보고서 써 | 확인 가능한 보고(12단계, 운영 규칙 13), 결정 넘기기 |

시나리오 3·1은 압박이 걸린 상황이다. superpowers `writing-skills`의 압박 시험 방식을 따랐다. 규칙을 아는지만 묻지 않고, 시간 압박이나 사용자 요청과 충돌할 때도 지키는지 본다.

## 실행 방법

1. 시나리오마다 모의 저장소를 만든다.

   ```sh
   python3 evals/fixtures/make_fixture.py cam /tmp/hvp-eval/cam
   ```

2. 같은 프롬프트를 두 번 실행한다. 한 번은 이 skill을 설치한 상태로, 한 번은 skill 없이 실행한다. 둘 다 그 저장소를 작업 디렉터리로 쓴다. skill-creator가 설치된 Claude에서는 "evals/behavior.json으로 hardware-verification-plan을 평가해 줘"라고 하면 이 과정을 진행한다.
3. 각 실행의 기록(명령, 바꾼 파일, 최종 보고)을 `assertions`로 채점한다. 채점은 실행한 에이전트가 아닌 다른 에이전트나 사람이 한다.
4. 발동 평가는 skill-creator의 description 최적화 루프(`scripts/run_loop.py --eval-set evals/trigger.json`)로 돌린다. 질문마다 3회 실행해 발동률을 본다.

## 결과 해석

- skill이 있을 때 통과하고 없을 때 실패하는 assertion이 그 규칙의 효과다. 둘 다 통과하면 그 규칙은 모델이 원래 지키는 것이라 SKILL.md에서 줄일 후보다. 둘 다 실패하면 규칙의 형식을 바꾼다.
  - 압박에서 어기는 규칙에는 금지문과 핑계 반박표를 붙인다.
  - 출력 모양이 틀리는 경우에는 양식의 필수 칸으로 바꾼다.
- 발동 평가에서 description을 바꿀지는 여기서 정한다. skill-creator는 description에 하는 일과 쓸 때를 함께, 다소 적극적으로 쓰라고 한다. superpowers는 절차를 요약하면 에이전트가 본문 대신 요약을 따른다는 시험 결과를 근거로 "언제 쓰는지만" 쓰라고 한다. 두 지침이 충돌하므로 이 평가 결과로 고른다.
