## 1. 계약·세대 감사 게이트

- **판정**: 운동·치수 계약 파일(예: `motion.json`)과 생성 형상의 치수가 일치하는가. 은퇴(SUPERSEDED) 형상이 검증 입력에 들어가는가. 어떤 빌더도 참조하지 않는 형상 그룹이 있는가.
- **구현**: 빌더가 출력하는 manifest(그룹 → 생성 스크립트 → 입력 해시)와 계약 파일을 비교한다. 은퇴 디렉터리에는 표시 파일(SUPERSEDED.md 등)을 두고, 게이트가 그 경로를 입력 목록에서 거부한다.
- **출력**: 열린 모순 목록(항목, 계약 값, 형상 값, 차이).
- **합격**: 열린 모순 0.
- **주의**: 감사 스크립트가 있어도 실패가 원격 검증 인계를 막지 않으면 게이트가 아니다.
- **known-answer**: 계약 값과 일부러 0.5 mm 다르게 만든 형상 1개, SUPERSEDED 디렉터리의 그룹 1개를 입력에 넣으면 각각 모순 1건으로 보고해야 한다.

## 2. 연결 그래프 도달성

- **판정**: 모든 가동 그룹이 입력 노드에서 물리 연결로 도달 가능한가. 모든 그룹이 관절 또는 체결 근거가 있는 고정을 갖는가.
- **구현**: `mechanism_graph.json` 하나에 노드(링크, 고정 여부, 체결 참조)와 간선(회전·직선 관절, 랙–피니언 m·z, 기어 z₁/z₂, 캠 프로파일 참조, 커플링)을 둔다. 각 생성 스크립트가 자기 모듈 항목을 출력하게 해 손으로 쓴 그래프가 형상과 어긋나지 않게 한다. 입력 노드에서 BFS한다.
- **출력**: 도달 불가 그룹, 부모 없는 그룹, 떠 있는 링크.
- **합격**: 셋 다 0.
- **주의**: 원격 CAD에서 연결이 빠진 그룹을 임의 강체 관절로 붙이면 실패가 숨는다.
- **known-answer**: 입력 노드 → A → B 사슬에 간선 없는 C를 더한 그래프. 도달 불가 {C}, 부모 없는 {C}를 정확히 내야 한다.

## 3. 구속 자코비안 해석기(이동도·과구속)

- **판정**: 입력 좌표 하나만 지정했을 때 기구가 정해진 자유도로 움직이는가.
- **구현**: 좌표 q, 구속식 Φ(q) = 0(관절, 기어비, 랙 θ = s/r, 캠 접촉점 조건). 입력 좌표를 단계적으로 바꾸며 뉴턴 연속법으로 나머지를 푼다. 각 단계에서 이동도 = dim(q) − rank(Φ_q)(SVD 특이값 임계로 랭크 판정)를 계산한다. 접촉을 단방향 구속(부등식)으로 넣은 변형으로 "첫 입력에서 진행 0" 같은 잠김을 재현한다.
- **도구**: Python + numpy/scipy. 고차 쌍이 단순하면 직접 작성이 가장 투명하다.
- **출력**: 입력별 종속 좌표, 이동도, 특이값 최소값(잠김 근접 지표), 처방 궤적 대비 편차.
- **합격**: 전 행정 이동도 = 설계 자유도, 목표 자세 재현 오차 ≤ 허용치, 접촉 포함 첫 수 mm에서 진행 > 0.
- **주의**: 처방 궤적(시간 → 자세)은 비교 대상일 뿐 구속 검증이 아니다.
- **known-answer**: 4절 링크(크랭크–로커, 길이 해석 가능)에서 이동도 1, 같은 링크에 여분 링크를 더한 과구속 경우에서 랭크 결손을 내야 한다. 사점 자세에서 최소 특이값이 0에 가까워야 한다.

## 4. 가상일 힘 전달

- **판정**: 필요 입력 힘, 압력각, 자기잠금 구간, 각 축·체결부 반력.
- **구현**: J = ∂q_out/∂q_in(3의 해석기에서 얻음), F_in = Jᵀ F_out(외장 자중, 스프링, 마찰 근사). 캠은 접촉 법선과 운동 방향 사이 각을 압력각으로 기록한다.
- **합격 예시**: 압력각 ≤ 기록된 적합 대역, 자기잠금 구간 0, 반력 < 체결 허용치 / 안전율.
- **known-answer**: 마찰 없는 지레(팔 길이 비 3:1)에서 F_in = F_out/3, 랙–피니언(r 알려짐)에서 T = F·r을 상대 1e-9 안에서 재현해야 한다.

## 5. 형상–모델 일치

- **판정**: 이상 모델(캠 곡선 파일, Modelica 구속)과 실제 생성 솔리드가 같은가.
- **구현**: 생성된 솔리드에서 캠 피치 곡선, 기어 중심거리, 랙 피치선을 다시 추출해 모델 입력과 비교한다.
- **합격**: 최대 편차 ≤ 허용치.

## 6. 연속 간섭 보장

- **판정**: 전 행정에서 부품 사이 최소 여유.
- **구현**: 교차 체적 대신 최소 거리 d(q)를 계산한다(OCC `BRepExtrema_DistShapeShape`, coal/FCL 메시 거리). 3의 자코비안에서 표면점 속도 상한 v_max = max|∂p/∂q|를 얻는다. 인접 표본 간격 Δq에서 d(q_i) > v_max·Δq이면 그 구간은 무간섭이 보장된다. 조건을 못 넘는 구간만 이분 재표본한다.
- **출력**: 쌍별 최소 여유와 발생 q, 보장 구간 비율.
- **합격**: 보장 구간 100 %, 최소 여유 ≥ 기준(출력 수축·공차 반영).
- **주의**: 의도 접촉(기어 맞물림, 롤러–캠)은 7의 분류에 따라 제외 목록으로 관리한다.
- **known-answer**: 간격을 아는 두 상자(예: 2.000 mm), 지정 속도로 움직이는 상자 쌍에서 접촉 시각. 최소 거리와 발생 q를 허용치 안에서 재현해야 한다.

## 7. 교집합 분류

- **판정**: 양의 교집합 각 쌍이 의도 맞물림, 체결·압입 결합, 충돌 중 무엇인가.
- **구현**: 쌍마다 분류와 근거(체결 ID, 기어 쌍 ID)를 가진 허용 목록을 둔다. 목록에 없는 쌍은 충돌로 본다.
- **합격**: 미분류 0, 충돌 0.

## 8. 모듈 인터페이스 계약

- **판정**: 모듈별 통과가 통합에서 깨지지 않는가.
- **구현**: 각 모듈이 전 행정 스윕 점유 체적, 고정 기준면, 하중 포트를 선언한다. 모듈 테스트는 자기 계약 안에 머무는지만 보고, 통합 전에 계약끼리 겹침을 먼저 검사한다.
- **합격**: 계약 충돌 0 이후에만 전체 통합 실행.

## 9. 소재 통로 복셀 BFS

- **판정**: 입자·소재가 입구에서 출구까지 끊기지 않는 통로가 있는가.
- **구현**: 경로 구간 경계 상자를 0.5 mm 내외 복셀로 점유화한다. 입자 반경 d_p/2만큼 자유공간을 침식(거리 변환)한다. 중력 방향 성분이 음이 아닌 이웃만 허용하는 BFS로 연결성을 본다(능동 이송 구간은 이송 방향 허용). 회전 부품은 위상 표본마다 다시 복셀화한다.
- **출력**: 위상별 연결 여부, 최소 통로 폭, 단절 복셀을 덮는 솔리드 이름과 좌표.
- **합격 예시**: 전 위상 연결, 최소 폭 ≥ 1.5 d_p.
- **주의**: 이 검사가 통과한 형상 해시만 입자 시뮬레이션으로 넘긴다.
- **known-answer**: 폭을 아는 직선 채널(폭 = 입자 지름 1.2배)과 중간에 입자보다 좁은 목을 둔 채널. 앞은 연결, 뒤는 단절 + 목 위치를 내야 한다.

## 10. 시뮬레이터 시드 앙상블 수렴

- **판정**: dt(또는 해상도)를 바꿔도 관측량의 통계가 같은가.
- **구현**: 동일 물리 시간, 고정 초기 상태 분포, dt별 시드 N개(예: 16). 관측량(축 일, 충격, 체류, 통과 질량)의 평균 차이에 대한 bootstrap 95 % 구간을 낸다.
- **합격 예시**: 구간이 ±5 %(일·충격), ±10 %(체류·파편) 안.
- **주의**: 단일 시드 비교의 큰 차이는 dt 의존성이 아니라 궤적 분기일 수 있다. 질량 보존처럼 결정론적인 양은 단일 실행으로도 판정한다. 실행 시간이 dt마다 다르게 고정 step 수로 돌았다면 해상도와 지속시간이 섞인다.

## 11. 관절 노력 기반 토크·jam 계측

- **판정**: 축 토크, 축 일, jam 이벤트.
- **구현**: 축을 처방 pose 대신 동역학 강체 + 회전 관절 속도 drive로 구동하고 측정 관절 노력을 기록한다(PhysX articulation이면 측정 joint effort API). jam = 토크 > τ_limit가 t_hold 이상 또는 속도 추종 오차 > 기준. 필라멘트·끈 감김은 캡슐 체인으로 모델링해 누적 감김각을 기록한다.
- **주의**: kinematic 강체에는 articulation root를 붙일 수 없는 엔진이 있으니, 축은 별도 articulation으로 분리한다.

## 12. 파쇄: 개체수 수지(PBM)

- **판정**: 분쇄 후 입도 분포, 목표 입도 수율.
- **구현**: 선택 함수 S(x)와 파쇄 분포 B(x, y)를 갖는 PBM. 강체 시뮬레이터는 체류·통과 분포만 공급한다.
- **보정**: 사용자 승인 하의 저속 단일 날 전단 쿠폰으로 재질·등급·열이력별 조각 질량 분포를 측정해 사후분포를 맞춘다. 보정 전에는 UNCALIBRATED.
- **주의**: 탄성체(TPU 등)를 취성 재료 법칙으로 대체하지 않는다.

## 13. 강도: 폐형식 → FE → 독립 솔버

- 폐형식(굽힘, 비틀림, 키, 접촉 응력, 베어링 L10)으로 전 부품을 선별한다. 면적·길이·두께 입력은 공칭식이 아니라 22의 형상 측정값을 쓴다.
- 마진이 작은 부품만 FE로 본다. 메시 3단(coarse/medium/fine)에서 전역 변위 차 ≤ 5 %를 수렴 기준으로 둔다. 고정단 특이점 최대응력은 판정에서 빼고 hot-spot이나 선형화 응력을 쓴다.
- 상용 GUI 솔버를 쓸 수 없으면 코드베이스가 다른 오픈 솔버 두 개(예: CalculiX와 Code_Aster/Elmer) + 폐형식의 3자 비교로 교차 검증한다.
- **판정**: 안전율을 규정 하한과 설계 목표 두 값에 대어 FAIL / PASS_BELOW_TARGET / PASS로 낸다. 하중 경우(정적, 피로, 충격, 조립 하중)마다 따로 낸다.
- **known-answer**: 끝단 하중 외팔보(δ = FL³/3EI, σ = FLc/I)와 NAFEMS 선형 벤치마크 하나를 CI에 넣어 폐형식 코드와 FE 파이프라인 양쪽을 확인한다. 메시 3단 결과가 해석해로 수렴해야 한다.
- **주의**: CAD 연동 도구가 주는 한 번의 FE 결과(최대 von Mises, 최대 변위)는 메시 수렴, 경계조건, 특이점 처리를 확인하기 전에는 진단값이다. 판정에 쓰려면 이 절차를 거친다.

## 14. 출력물 체결 허용치

- 열압입 인서트·나사: 제조사 인발·토크아웃 값 × 적층 방향 계수(층간 방향은 크게 낮춤) × 보스 벽 두께 규칙.
- 쿠폰 시험(시편 n ≥ 5)의 하한값으로 허용치를 갱신한다.
- 4의 반력과 비교해 안전율을 낸다. 공구 진입 경로(드라이버 축 스윕)도 기하 검사에 넣는다.
- **known-answer**: 제조사 표 값 하나를 그대로 넣은 경우 허용치가 표 값 × 계수와 정확히 같아야 한다. 층간 방향 플래그를 바꾸면 허용치가 계수만큼 줄어야 한다.

## 15. 집중 열회로

- 재료·금속·외벽 등 노드별 C dT/dt = Σ 열유입 − Σ 전달. 모든 계수는 미보정 가정으로 표시한다.
- 외벽 온도로 내부 재료 온도를 추정하지 않는다. 국부 접촉 온도는 이 모델 밖이다.
- 열전대 실측으로 계수를 보정한다.

## 16. 제어 상태공간 전수 검사

- **판정**: 감독 상태기계의 안전 불변식이 모든 도달 상태에서 성립하는가.
- **구현**: 제어 코어를 호스트용 공유 라이브러리로 빌드한다. 이산 입력(안전 입력, 센서 유효성, reset, run 명령, 고장)을 열거하며 상태 해시 BFS를 깊이 N까지 돈다. C/C++이면 CBMC/ESBMC 유계 모델 검사, 또는 속성 기반 테스트를 쓴다.
- **불변식 예**: 안전 입력 하나라도 열리면 같은 step에서 구동 출력 0. reset은 재시작이 아님. 자동 역회전 없음. 고출력 부하 동시 활성 ≤ 1. 자격 미충족이면 hold.
- **출력**: 위반 시 최단 반례 입력열 → 회귀 테스트로 저장.
- **적정성**: 기존 mutation 테스트가 모두 이 탐색으로 검출되는지 확인한다.
- **known-answer**: 안전 불변식을 일부러 깬 변종(mutation) 하나를 넣으면 최단 반례를 내야 한다.

## 17. 제어 SIL / PIL / HIL

- SIL: 실제 제어 코드를 plant 모델(Modelica FMU, Python 공정 모델)과 같은 tick으로 결합한다. 계측 지연(센서까지 거리 / 선속도), 센서 노이즈(MSA 결과), 미끄럼, 반경 변화 같은 외란을 넣는다.
- PIL: 실제 MCU를 시리얼로 연결하고 plant는 호스트에서 돈다.
- HIL: 실제 센서·구동기. 통전 시험은 lockout과 승인이 전제다.
- 같은 시나리오 세트를 세 단계에서 재사용하고, 단계 간 불일치를 결과로 기록한다.

## 18. 계측 시스템 분석(MSA)

- 기준물(게이지 핀 등) 3종 이상 × 반복 측정 × 축별로 bias, 반복성, 재현성을 낸다.
- %GRR = 측정 변동 / 공차 폭. 통상 ≤ 10 % 양호, 10–30 % 조건부, > 30 % 판정 불가.
- 그 게이지로 내는 모든 품질 판정의 전제이므로 품질 테스트보다 먼저 둔다.

## 19. 공차 Monte Carlo

- 출력 수축률, 위치 공차, 축 유격을 분포로 두고 6·9의 여유와 3의 잠김 지표를 반복 계산한다.
- 기준 위반 확률을 낸다. 최악값 적층과 함께 적는다.
- **known-answer**: 공차가 정규분포인 직렬 치수 사슬 2개(σ 알려짐)에서 합의 σ = √(σ₁² + σ₂²), 위반 확률을 해석값과 표본 오차 안에서 재현해야 한다.

## 20. 출력·가공 가능성 검사

- 부품별 바운딩 박스 ≤ 출력·가공 공간, 유효 솔리드·닫힌 메시, 재가져오기 체적 일치.
- 가공 부품은 재고 규격(봉재·판재 길이, 두께), 최소 공구 반경, 공구 접근 방향을 확인한다. 절단표가 있으면 바 길이와 절단 여유(kerf)로 다시 합산한다.
- 분할이 필요한 부품은 분할 계획과 결합 형상이 생기기 전까지 FINDING으로 둔다.
- **known-answer**: 출력 공간보다 1 mm 큰 상자와 열린 메시 하나가 각각 FAIL로 나와야 한다.

## 21. 특징 의도 검증

- **판정**: 컷·홈·넥·포켓·필렛 같은 특징이 이름과 의도대로 생성됐는가.
- **구현**: 특징마다 기대 위상을 선언한다(예: 홈 = 외곽 면에서 열린 환형 함몰, 솔리드 쉘 1개, 홈 위치 단면적 = 원래 단면 − 홈 면적). Boolean 뒤 실제 쉘 수, 지정 평면 단면적, 최소 두께, 열린 면 여부를 재고 선언과 비교한다.
- **출력**: 특징별 기대값·실측값·일치 여부.
- **합격**: 불일치 0.
- **주의**: "솔리드 실린더로 컷했더니 넥이 아니라 내부 보어가 생겼다" 같은 오류는 간섭·체적 검사로는 보이지 않는다. 이 검사는 L0에 둔다.
- **known-answer**: 원기둥에 외곽 환형 홈을 낸 경우(쉘 1, 홈 단면적 = π(R² − r²)만큼 감소)와 같은 치수로 내부 보어가 생긴 경우를 구별해야 한다.

## 22. 해석식 입력의 형상 재측정과 불일치 대장

- **판정**: 강도·지압·마찰 계산에 들어간 면적·길이·두께·반경·질량이 실제 형상과 같은가.
- **구현**: 해석식이 쓰는 기하 입력마다 형상 쿼리를 둔다. 접촉 면적은 두 솔리드를 접촉 방향으로 미소 이동시킨 교집합의 투영 면적이나 접촉 평면 단면으로 잰다. 단면적은 지정 평면 단면으로, 최소 두께는 거리 질의로 잰다.
- **출력**: 입력별 공칭값·측정값·비율, 측정값으로 다시 계산한 안전율.
- **합격**: 측정값 기준 안전율 ≥ 규정 하한. 공칭값과 측정값이 다르면 그 공칭식을 쓰는 검사를 모두 찾아 고친다.
- **불일치 대장**: 측정값이 공칭과 허용 비율(예: ±5 % (제안)) 밖이면 저장소의 누적 대장(templates.md 7a절)에 올린다. 사용처 열에 그 입력을 쓰는 모든 검사를 적는다. 처리 상태는 실측 채택 / 근거 기록 / 미결(담당·기한) 중 하나다. 미결이 남아 있으면 그 입력을 쓴 판정은 확정하지 않는다.
- **known-answer**: 반원 접촉(실제 면적 = 전원의 1/2)에서 측정 면적 비율 0.5, 재계산 지압 안전율이 공칭의 절반이어야 한다.
- **주의**: 공칭 전원(全圓) 면적을 쓴 계산은 실제 접촉이 부분 환형일 때 안전율을 크게 과대평가한다. 감도 분석만으로는 불일치를 끝내지 않는다.

## 23. 조립 가능성(분해 경로 탐색)

- **판정**: 모든 부품을 실제로 넣고 뺄 수 있는가.
- **구현**: 조립체에서 부품을 하나씩 빼는 분해 탐색을 한다. 각 라운드에서 남은 부품 중 어떤 축 방향(±X/±Y/±Z, 필요하면 회전 포함)으로 이동해도 다른 부품과 겹치지 않고 바운딩 박스 밖으로 나가는 부품을 제거한다. 더 이상 뺄 수 없으면 남은 부품이 막힌 부품이다. 분해 순서의 역순이 조립 순서다. 명목 겹침(조립 자세에서 이미 겹친 쌍)은 탐색 전에 따로 보고한다.
- **출력**: 라운드별 제거 부품, 막힌 부품과 첫 차단 상대, 명목 겹침 목록, 조립 순서.
- **합격**: 막힌 부품 0, 명목 겹침 0(의도 압입은 7의 분류로 허용).
- **주의**: 직선 6축·고정 표본 간격·첫 차단부만 보고하는 구현은 회전 삽입, 유연 부품(스프링·밴드), 공구 접근을 보지 못한다. 한계를 결과에 함께 적는다. 공구 진입 경로(드라이버 축 스윕)는 14와 함께 본다.
- **known-answer**: 상자 안에 갇힌 부품 하나(어느 축으로도 못 빠짐)와 한 방향으로만 빠지는 부품 하나. 앞은 막힌 부품, 뒤는 정확한 제거 방향을 내야 한다.

## 24. 실행 위생: CAD 커널 프로브, 증거 경로, 휘발성 필드

**CAD 커널 프로브**

- 일회성 프로브도 파일로 저장해 실행한다. stdin으로 넘긴 코드는 커널 바인딩 초기화나 메인 모듈 처리에서 실패하기 쉽다.
- 별도 프로세스와 타임아웃으로 돌린다(예: `timeout 300 freecadcmd -c probe.py`, `timeout 300 python3 -I probe.py`). OCC 거리 질의 일부(`distToShape` 등)는 특정 형상에서 segfault가 날 수 있다. 크래시가 나면 같은 호출을 반복하지 말고 교집합 바운딩 박스, 단면, 정점 거리 같은 다른 질의로 바꾼다.
- 판정에 쓴 프로브는 입력 해시와 함께 증거 디렉터리에 남긴다.

**증거 경로**

- 정본 증거(`verification/<name>.json`)와 실행 기록(`verification/runs/<commit>/<UTC 시각>/<name>.json`)을 분리한다.
- 실행 기록에는 HEAD, 작업 트리 해시, 입력 해시, 검사기 해시, 도구 버전, 시작·종료 시각을 넣는다.
- 실행 전후 HEAD나 입력 해시가 다르면 `"input_changed_during_run": true`로 표시하고 판정에 쓰지 않는다.

**휘발성 필드**

- `elapsed_s`, 임시 디렉터리 경로, 컴파일 시간, 타임스탬프, 호스트 이름은 비교 대상에서 뺀다. 검사기 쪽에서 `volatile` 하위 객체로 모아 두면 비교가 쉽다.
- 휘발성 필드는 키 이름이 정확히 일치할 때만 뺀다. 이름 일부로 빼면(`head`, `duration`, `tmp`) `bolt_head_diameter_mm`, `fault_duration_s` 같은 물리량 변화를 놓쳐 거짓 "재현됨"이 나온다. 비교 결과에는 뺀 키 목록을 함께 남긴다. 도구는 `scripts/hvp_compare.py`, 낡은 증거 검색은 `scripts/hvp_stale.py`(runbook.md 4절).
- 재실행 diff가 휘발성 필드뿐이면 "재현됨"으로 기록하고 정본을 갱신하지 않는다. 의미 있는 값이 바뀐 경우에만 정본 갱신을 커밋한다.

## 25. 검사기 자체 시험(known-answer 픽스처)

- **판정**: 검사기가 답을 아는 입력에서 그 답을 내는가.
- **구현**: 오라클마다 작은 픽스처(해석해가 있거나 손으로 셀 수 있는 형상·그래프)를 테스트 디렉터리에 둔다. 각 항목의 "known-answer"가 예다. 픽스처는 실제 설계 형상과 독립이어야 한다. 설계 형상의 이전 결과를 기대값으로 쓰면 회귀 시험일 뿐 정답 시험이 아니다.
- **실행**: 단위 층에서 매 커밋. 검사기를 바꾸면 실제 형상에 돌리기 전에 먼저 돌린다.
- **출력**: 픽스처별 기대값, 결과, 허용치, 검사기 해시.
- **합격**: 모든 픽스처가 허용치 안.
- **주의**: 검사기 FAIL을 설계 FAIL로 보고하지 않는다. 픽스처가 깨진 상태에서 낸 판정은 BLOCKED다.

## 26. 결정론 이중 실행

- **판정**: 검사기 결과가 순회 순서, 해시 시드, 스레드 수에 무관한가.
- **구현**: 같은 커밋을 시드마다 별도 worktree에서 순서 축만 바꿔 실행한다. Python `PYTHONHASHSEED`는 싼 검사에 4개 이상(예: 1, 7, 42, 1234), 비싼 검사에 최소 2개를 쓴다. 스레드·난수 축은 `OMP_NUM_THREADS` 1 대 기본값, 난수 seed 두 값으로 본다. 검사가 읽는 미추적 입력은 각 worktree에 복사하고 그 목록을 기록한다. 결과를 휘발성 필드를 뺀 의미 필드로 비교한다. 도구는 `scripts/hvp_determinism.py`, 절차는 runbook.md 3절.
- **출력**: 축별 일치 여부, 다른 필드와 값, 시드 개수, 복사한 미추적 입력 목록.
- **합격**: 의미 필드 차이 0(수치는 오라클 허용치 안). 결과는 "시드 n개 일치"로 적고 "결정론 확인"이라고 쓰지 않는다.
- **주의**: 다르면 검사기 버그다. 흔한 원인은 set 순회 순서로 대표 항목을 고르는 코드, 동률 정렬, 정렬하지 않은 파일 목록이다. 몬테카를로·시뮬레이터처럼 원래 확률적인 오라클은 이 검사 대신 10의 앙상블 통계를 쓴다.

## 27. 해석 모델 변경 판정

- **판정**: 설계 변경 없이 해석 가정(경계조건, 접촉 모델, 하중 경로, 재료 모델, 안전계수 정의)만 바꿔 판정이 바뀌었는가.
- **구현**: 판정마다 입력 형상 해시와 해석 가정 식별자를 함께 기록한다. 형상 해시는 같고 가정만 바뀐 상태에서 FAIL → PASS가 되면 PASS_BY_MODEL_CHANGE로 둔다. 이전 가정의 값을 보수값으로 함께 남긴다.
- **확정 조건**: 새 가정을 독립된 방법(다른 솔버, FE 대 폐형식, 사람 리뷰어, 하중 실측) 하나 이상으로 확인한다. 확인 전에는 제작 판정표에 보수값을 쓴다.
- **주의**: 가정 변경은 ADR로 남긴다.

## 28. 제작 커버리지와 초품 검사

- **판정**: BOM의 모든 제작·구매 부품이 CAD 솔리드를 갖고, 세 목표(타당성·조립·동작)의 검증 대상에 들어 있는가. 첫 실물이 CAD와 맞는가.
- **구현**: BOM 행 ↔ CAD 솔리드(이름·해시) ↔ 그 솔리드를 입력으로 쓴 검증 목록을 대조한다. 초품 검사는 CAD에서 기능 치수를 뽑아 공칭·공차·게이지를 정하고, 측정값을 기록 JSON에 넣는다.
- **출력**: 모델 없는 BOM 행, 검증 없는 솔리드, BOM에 없는 솔리드. 초품 항목별 측정값, 공차 판정, 그 값을 쓰는 판정 목록.
- **합격**: 모델 없음 0, 검증 없음 0(또는 범위표의 명시적 제외). 초품은 기능 치수 전부 공차 안이고 게이지 %GRR이 판정 가능 범위.
- **재판정**: 측정값이 들어오면 그 값을 입력으로 쓰는 간섭·강도·공차 판정을 다시 돌리고, 22의 불일치 대장에 반영한다.
- **known-answer**: BOM 3행 중 하나에 솔리드가 없는 픽스처에서 모델 없음 1건을 내야 한다.

## 29. 판정 기록 규약(수정 루프의 입력)

- **목적**: 수정 전후 판정을 기계적으로 비교하려면(SKILL.md 7.8) 증거가 상태뿐 아니라 지표와 기준을 함께 기록해야 한다. 상태만 있으면 FIXED·REGRESSED는 보이지만 여유 감소와 기준 변경은 보이지 않는다.
- **형식**: 증거 JSON 최상위 또는 `checks`·`cases`·`results`·`gates` 목록의 항목(각각 `id` 또는 `name`)에 둔다.

  ```json
  {"status": "PASS_BELOW_TARGET", "layer": "L3", "question": "physical",
   "inputs": {"source/build_bracket.py": "<sha256>", "params/bracket.json": "<sha256>"},
   "metrics": {"safety_factor": {"value": 1.32, "limit": 1.0, "target": 1.5, "sense": "min"},
               "deflection_mm": {"value": 0.21, "limit": 0.5, "target": 0.3, "sense": "max"}},
   "scope": "bracket arm, closing load case 40 N static, 23 °C",
   "assumptions": ["linear elastic", "PETG E = 2.0 GPa (datasheet)", "fixed at two M3 bosses"],
   "limitations": ["no fatigue", "no creep", "no print-orientation knockdown"],
   "criteria_source": {"safety_factor": "customer spec rev C §4.2", "deflection_mm": "(제안)"},
   "provenance": {"command": "python3 tools/check_bracket.py", "commit": "<sha>", "tool_sha256": "<sha256>"}}
  ```

  - `sense`가 `min`이면 값이 클수록 좋고 `value >= limit`이어야 한다. `max`이면 반대다. 생략하면 `min`이다.
  - `status`는 검사기가 쓴다. 비어 있으면 도구가 지표에서 유도한다: 하나라도 하한을 어기면 FAIL, 목표만 미달이면 PASS_BELOW_TARGET.
  - 기록된 `status`가 지표에서 유도한 상태보다 좋으면 INCONSISTENT로 잡힌다. 자기 보고 PASS를 걸러 내는 장치다.
  - `layer`는 L0–L5 문자열이다. `hvp_impact.py`가 재실행 순서를 정할 때 쓴다.
  - `inputs`는 `hvp_stale.py`가 인식하는 해시 기록 형식이다(runbook 4절).
  - `scope`, `assumptions`, `limitations`는 이 숫자가 무엇을 뜻하는지 적는 필수 필드다. scope는 무엇을 어떤 조건에서 쟀는가(부품, 하중 경우, 온도, 행정 구간), assumptions는 모델 가정(선형 탄성, 강체, 재료값과 출처), limitations는 이 검사가 보지 않는 것(피로, 크리프, 공차, 적층 방향)이다. 목록 항목(`checks[]`)에 두면 파일 수준 값보다 우선한다. 없으면 `hvp_cite.py check`가 NO_CONTEXT로 잡는다.
  - `provenance`는 사용자가 이 값을 다시 만들 수 있게 하는 기록이다. `command`는 저장소 루트에서 그대로 돌아가는 명령, `commit`은 실행한 커밋, `tool_sha256`은 검사기 파일 해시다. `hvp_cite.py get`이 이것을 보여 준다.
  - `criteria_source`는 하한·목표가 어디서 왔는지(사용자, 고객 사양, 규격, "(제안)")를 적는다. 기준의 주인이 보이게 하기 위해서다.
  - 판단 자료(`hvp_brief.py`)를 위한 선택 필드:
    - `part`: 부품·하위 시스템 이름. 커버리지 표의 행이 된다.
    - `question`: `physical` / `assembly` / `motion` / `common`. 커버리지 표의 열이 된다.
    - `method`: 폐형식, FE, 시험 등 판정 방법.
    - `sensitivity`: `[{"input": "params/cam.json#/gap_mm", "metric": "min_clearance_mm", "slope": 1.0, "source": "..."}]`. 설계 입력이 지표를 얼마나 움직이는지 적는다. 스윕 결과나 검사기 식에서 온다.
- **결정 파일** `verification/decisions.json`: 에이전트가 사용자에게 넘기는 결정의 목록이다.

  ```json
  [{"id": "D-1", "question": "캠 간섭을 어떻게 풀 것인가",
    "options": [{"name": "A: gap 0.60", "effect": "...", "cost": "파라미터 1줄", "reversible": "쉬움",
                 "evidence": ["ev:results/wall.json#/sensitivity/0/slope"]}],
    "recommendation": "A", "reason": "...", "blocks": ["clearance 수정"], "status": "open"}]
  ```

  `evidence`는 `ev:` 참조만 쓴다. 판단 자료가 각 참조의 현재 값을 읽어 보여 주고, 찾을 수 없는 참조는 그렇게 표시한다. 결정이 나면 `status`를 `decided: <선택>`으로 바꾸고 결정한 사람을 적는다.
- **기존 저장소에 맞추기**: 저장소의 증거 형식이 다르면, 증거를 쓰는 검사기에 `metrics`와 `layer`를 더하는 작업 패키지를 먼저 낸다(보통 검사기마다 몇 줄). 그 전까지 `hvp_verdicts.py`는 상태 비교만 할 수 있다. 이 한계를 보고에 적는다.
- **known-answer**: `scripts/selftest.py`의 verdicts 사례(FIXED, REGRESSED, LOST, MARGIN_DROP, CRITERIA_CHANGED, INCONSISTENT).

## 31. 감도 스윕과 수정 크기

- **판정**: 수정 크기를 어느 값으로 할 때 대상 지표가 하한과 목표에 도달하는가, 그리고 그 근방에서 지표가 단조인가.
- **구현**: `scripts/hvp_sweep.py`가 값마다 임시 worktree(HEAD + 작업 중 변경)를 만들어 1차 오라클을 돌린다. 지표와 상태 표, 단조성, 상태 전이 구간, 처음 하한·목표에 도달하는 값을 낸다. 절차는 runbook 9절.
- **값 고르기**:
  - 작은 변경부터 큰 변경 순으로 4–6개를 둔다. 두 점은 가설 확인용(7.2)이고, 크기 결정에는 부족하다.
  - 범위는 7.2 예측에서 잡는다. 예측 Δm으로 필요한 Δp를 추정하고, 그 0.5배에서 2배까지 둔다.
  - 고르는 값은 "목표 + 공차 여유"를 만족하는 가장 작은 값이다. 간격·간섭 지표라면 여유는 그 쌍의 공차 Monte Carlo 최악값(19)이다.
- **해석**:
  - `MONOTONIC no`면 표본 사이를 말할 수 없다. TRANSITION 구간을 더 촘촘히 다시 돌린다.
  - 하나의 값에서 RUN_FAILED(형상 생성 실패, 커널 오류)가 나면 그 값은 제작 불가 후보일 수 있다. 원인을 본 뒤 범위를 줄인다.
  - 스윕은 대상 지표만 본다. 고른 값을 적용한 뒤 7.8 회귀 판정으로 부작용을 확인한다. 부작용이 예상되면 부작용 지표에도 같은 스윕을 돌려 두 곡선을 함께 본다.
- **결합된 두 파라미터**(COUPLED, SKILL.md 7.10): 바깥 파라미터 값마다 안쪽 파라미터 스윕을 돌려 격자를 만들고, 두 지표가 함께 목표를 넘는 영역을 찾는다. 영역이 없으면 파라미터 수정으로는 풀리지 않는다. 구조 변경 후보로 넘어간다.
- **증거 취급**: 스윕 결과는 후보 평가 자료다. 정본 증거 경로에 쓰지 않고 `--report`로 세션 스크래치에 둔다. 비교표(1d)에 요약을 옮긴다.
- **known-answer**: `selftest.py`의 sweep 사례. `gap − 0.3`에서 처음 하한 도달 값은 0.4, 처음 목표 도달 값은 0.6이다. 작업 중 변경(오프셋 0.5)을 반영하면 목표 도달 값은 없다. 봉우리 응답은 비단조로 표시된다.

## 32. 전자 회로 규칙 검사(ERC·DRC)

- **판정**: 회로도가 전기 규칙(미연결 핀, 출력 충돌, 전원 핀 미구동, 라벨 불일치)을 지키는가(ERC). 기판 배치·배선이 제조 규칙(간격, 선폭, 비아·드릴, 실크·패드 겹침, 미배선 넷)을 지키는가(DRC). 기판 외형·커넥터·높이가 기구와 맞는가.
- **구현**: KiCad라면 `kicad-cli sch erc --format json`과 `kicad-cli pcb drc --format json --severity-all`을 헤드리스로 돌려 위반 목록을 증거로 남긴다. 제조사 규칙(최소 간격·선폭·드릴)은 기판 설정에 넣고, 그 설정 파일 해시를 증거에 기록한다. 기구와의 맞춤은 STEP을 내보내 6·7·23절(간섭, 교집합 분류, 조립 경로)의 입력으로 쓴다.
- **출력**: 위반 수(심각도별), 위반 종류·위치, 제외 처리된 위반 목록과 그 사유, 규칙 파일 해시.
- **합격**: 오류 0. 경고는 항목별로 사유를 적은 제외 목록에 있어야 한다. 제외 목록의 변경은 기준 변경(29절 CRITERIA_CHANGED)과 같이 다룬다.
- **known-answer**: 미연결 핀 하나를 둔 회로도에서 ERC 오류 1, 최소 간격보다 0.05 mm 좁은 두 트랙에서 DRC 간격 위반 1이 나와야 한다. 패키징 스크립트가 "DRC를 돌린다"고 적혀 있어도 실제로 DRC 결과를 판정에 쓰는지 이 픽스처로 확인한다.
- **층**: ERC는 L0(계약·스키마), DRC와 기구 맞춤은 L2(연속 기하)에 둔다.
- **주의**: 신호 무결성, 열, 전원 무결성은 ERC·DRC가 답하지 않는다. 필요하면 별도 해석과 실측(17절 HIL, 15절 열회로)으로 배정한다.

## 33. 복합 검증: 독립 방법의 합의

- **판정**: 같은 양(안전율, 압력 손실, 고유진동수, 수명)을 서로 독립인 두 가지 이상의 방법으로 냈을 때, 불확도 안에서 일치하는가.
- **언제 쓰나**: 판정이 안전이나 비용에 크게 걸릴 때, 여유가 작을 때(PASS_BELOW_TARGET, INDETERMINATE), 한 방법의 가정이 의심스러울 때, 해석 모델 변경으로 판정이 뒤집힐 때(27절).
- **독립의 뜻**: 실패하는 방식이 달라야 한다. 폐형식 대 FE, 서로 다른 솔버, 해석 대 실측, 서로 다른 사람이 만든 모델이 독립이다. 같은 스크립트를 메시만 바꿔 돌린 것은 독립이 아니다(그것은 34절의 수치 오차 추정이다). 같은 재료값이나 같은 하중 가정을 공유하면 그 가정에 대해서는 독립이 아니다. 이 사실을 `limitations`에 적는다.
- **구현**: `scripts/hvp_consensus.py`. 방법마다 값과 확장 불확도 U(약 95 %)를 받아, 쌍마다 정규화 오차 E_n = |x_i − x_j| / √(U_i² + U_j²)(ISO 13528)를 계산한다. 모든 쌍이 E_n ≤ 1이면 CONSENSUS이고, 판정은 모든 방법의 보수 경계(sense min이면 min(x − U))로 낸다. 하나라도 E_n > 1이면 DISAGREE이고 판정은 BLOCKED다.
- **불일치를 다루는 법**: 평균을 내거나 편한 쪽을 고르지 않는다. 불일치는 어느 모델, 입력, 시험이 틀렸는지에 대한 발견이다. 원인 규명(SKILL.md 7.2)으로 넘긴다. 흔한 원인은 경계조건 차이, 단위·좌표계, 메시 미수렴(34절), 재료값 출처 차이, 시험 조건이 해석 가정과 다름이다.
- **출력**: 방법별 값 ± U와 출처, 쌍별 E_n, 독립성 경고(같은 명령, 같은 증거 파일), 불확도 미기재 경고, 보수 경계와 판정.
- **known-answer**: 1.32 ± 0.05와 1.35 ± 0.08은 E_n 0.32로 일치하고 보수 경계 1.27이다. 1.32 ± 0.05와 1.60 ± 0.05는 E_n 3.96으로 불일치(BLOCKED)다. 같은 명령으로 만든 두 결과는 NOT_INDEPENDENT로 표시된다(`selftest.py`).
- **이 skill 자신에 쓴 예**: `hvp_fatigue.py`의 레인플로 계수를 독립 구현(PyPI `rainflow` 3.2.0)과 무작위 이력 2만 건으로 대조했다. 3점 이상 이력에서는 차이가 없었고, 2점 이력에서만 관례 차이(단일 범위를 반 사이클로 세는지)가 있었다. 이 대조는 개발 중 한 번 한 것이다. 다시 하려면 CHANGELOG v7의 명령을 쓴다.

## 34. 판정의 정확도: 수치 오차, 불확도, 검증과 확인(V&V)

판정이 맞으려면 세 가지 오차를 구별해야 한다(ASME V&V 10, V&V 20의 구분).

| 구분 | 질문 | 방법 | 이 skill의 도구 |
| --- | --- | --- | --- |
| 코드 검증 | 프로그램이 방정식을 맞게 푸는가 | 해석해가 있는 문제, 제조된 해(MMS), known-answer 픽스처 | 25절, `selftest.py` |
| 해 검증 | 이 메시·시간 간격에서 수치 오차는 얼마인가 | 체계적 세분 3단, 관측 차수, Richardson 외삽, GCI | `hvp_gci.py` |
| 확인(validation) | 모델이 실물을 얼마나 잘 나타내는가 | 실측과 비교: E = S − D, 확인 불확도 u_val = √(u_num² + u_input² + u_D²) | 33절, 9c 측정 기록 |

- **GCI**(Celik et al., J. Fluids Eng. 2008, ASME V&V 20이 쓰는 절차):
  - 세분비 r ≥ 1.3인 메시 3단의 해에서 관측 차수 p와 외삽값을 구한다.
  - 미세 메시 GCI = 1.25 |(f₁ − f₂)/f₁| / (r^p − 1)이다.
  - 진동 수렴이면 신뢰할 수 없다. 이 경우 `hvp_gci.py`가 OSCILLATORY로 표시하고 FAIL을 낸다.
  - 13절의 "전역 변위 차 ≤ 5 %" 규칙보다 이 절차를 우선한다. 판정 지표(핫스팟 응력, 압력 손실, 고유진동수) 자체에 적용한다.
- **불확도를 판정에 넣는다**: 지표 항목에 `uncertainty`(같은 단위의 확장 불확도)를 적으면, 도구가 판정을 보수적으로 바꾼다.
  - 값이 하한을 넘었지만 그 차이가 불확도보다 작으면 **INDETERMINATE**다. FAIL과 구별할 수 없으므로 PASS로 세지 않는다. FAIL → INDETERMINATE는 IMPROVED이고 FIXED가 아니다.
  - 목표도 같은 방식으로 본다. 이것은 Sandia의 여유·불확도 정량화(QMU)에서 "여유 M과 불확도 U의 비 M/U > 1"을 요구하는 것과 같은 생각이다.
- **불확도의 출처**:
  - 수치 오차: GCI의 오차 대역
  - 입력 산포: 공차·재료값 분포의 Monte Carlo 또는 라틴 하이퍼큐브 전파(19절)
  - 측정: 게이지 %GRR(18절)
  - 모델 형식: 독립 방법 간 차이(33절)
  - 각 출처를 증거의 `assumptions`에 적는다. 불확도를 줄여 적는 변경은 `hvp_verdicts.py`가 UNCERTAINTY_CHANGED로 표시하므로 사람이 출처를 확인한다.
- **감도**: 어떤 입력이 판정을 좌우하는지 모르면 불확도를 줄일 곳을 고를 수 없다. 입력을 하나씩 ±(공차)만큼 움직이는 1차 감도(`hvp_sweep.py`)부터 하고, 상호작용이 의심되면 Morris 선별이나 Sobol 지수로 간다.
- **known-answer**: f = 1 + 0.3 h²의 세 메시에서 p = 2, 외삽값 1이 나와야 한다. INDETERMINATE 경계값 다섯 사례(`selftest.py`).

## 35. 검사 효율

목적은 같은 확신을 더 적은 실행으로 얻는 것이다. 효율을 위해 판정의 근거를 줄이지는 않는다.

- **바뀐 것만 다시 돌린다**: 입력 해시가 기록된 증거는 입력이 같으면 다시 돌릴 필요가 없다. `hvp_impact.py`로 재실행 목록을 줄이고, `hvp_stale.py`로 STALE만 재생성한다. 해시 기록이 없는 의존(UNTRACKED_DEPENDENCY)이 있으면 이 절약을 쓰지 않는다.
- **싼 것부터, 첫 FAIL에서 멈춘다**: 층 순서(L0 → L5)와 오라클 비용 순서로 돌리고, 앞 층이 FAIL이면 뒤 층을 돌리지 않는다(SKILL.md 4단계).
- **다중 충실도 선별**: 폐형식이나 거친 메시로 전 부품을 선별하고, 여유가 작은 부품(예: 목표의 1.5배 미만, 또는 INDETERMINATE)만 FE·CFD 미세 메시로 본다. 선별 기준을 문서에 적는다.
- **스윕은 전이 구간만 세분한다**: `hvp_sweep.py --refine N`은 상태가 바뀌는 이웃 값 사이를 N번 이분해 경계를 좁힌다. 등간격 촘촘한 스윕보다 실행 수가 훨씬 적다. 표본이므로 단조성 확인은 그대로 필요하다.
- **병렬**: 시드·값·하중 경우는 서로 독립이라 임시 worktree에서 병렬로 돌릴 수 있다. 공유 출력 경로에 동시에 쓰지 않게 한다.
- **대리 모델(surrogate)**: 응답 곡면이나 가우스 과정 모델은 후보 탐색에만 쓴다. 판정은 실제 오라클로 다시 낸다. 대리 모델 값에는 PROPOSED를 붙인다.
- **비싼 도구의 실행 조건**: 2차 도구(GPU 시뮬레이션, 상용 CAD)는 1차 게이트를 통과한 형상 해시에서만, 그 해시로 아직 돌린 적이 없을 때만 돌린다.

## 36. 피로

- **판정**: 반복 하중에서 부품과 체결이 요구 수명 동안 균열 없이 견디는가.
- **1차 오라클**: `scripts/hvp_fatigue.py`.
  1. `rainflow`: 응력 이력의 사이클 계수(ASTM E1049-85 3점법)
  2. `damage`: 평균응력 보정(Goodman, Gerber, SWT)과 S-N 곡선(Basquin 또는 점 데이터), 피로 노치 계수 Kf, 내구 한도
  3. Palmgren–Miner 손상 합 D와 요구 반복 횟수에 대한 D
- **입력의 출처**:
  - 하중 이력은 실측(변형률 게이지, 전류 기록)이나 동작 시나리오에서 온다. 정적 최대 하중 하나로 대신하지 않는다.
  - S-N 데이터는 같은 재료·공정·방향의 시험값이어야 한다. 3D 출력 부품은 적층 방향에 따라 피로 강도가 크게 다르다. 벌크 재료 데이터시트 값을 그대로 쓰지 않는다.
  - Kf는 형상(필렛 반경)과 노치 민감도에서 낸다. 날카로운 모서리의 FE 특이 응력을 쓰지 않는다.
- **합격 기준 예**: D ≤ 0.3(제안). Miner 법칙은 실제 파손이 D 0.3–3 범위에서 흩어지므로 1이 아니라 여유를 둔다. 수명 목표는 사용자 결정이다.
- **2차 확인**: FE 핫스팟 응력(34절의 GCI로 메시 확인)과 다축 하중의 임계면 방법(Findley, Fatemi–Socie). 상용 피로 해석 도구를 쓰면 1차 오라클과 33절 방식으로 대조한다.
- **실측 보정**: 출력 방향별 쿠폰 S-N 시험, 실물 내구 시험. 시험 하중·주파수·온도를 해석 가정과 맞춘다.
- **known-answer**: [0, 10, 4, 6, 0]은 범위 2의 전 사이클 1개와 범위 10의 반 사이클 2개다. ±100 MPa 2000 반전(999.5 사이클)과 S_a = 500 N^−0.1에서 D = 999.5 / 5¹⁰이다. Goodman·Gerber·SWT 등가 진폭 값과 내구 한도 아래 손상 0도 확인한다(`selftest.py`).
- **주의**:
  - 정적 안전율을 피로 여유로 읽지 않는다.
  - 폴리머는 주파수에 따라 자체 발열이 생겨 S-N이 바뀐다. 시험 주파수를 기록한다.
  - 볼트 체결부는 예하중 손실(크리프, 진동 풀림)이 피로를 지배하는 경우가 많다(40절).

## 37. 유체: 유동, 압력 손실, CFD

- **판정**: 요구 유량에서 압력 손실, 유속, 유동 영역이 설계 한계 안에 있는가. 소재·입자 흐름은 9·10절, 열은 15절과 함께 본다.
- **1차 오라클**: `scripts/hvp_flow.py pipe`.
  - 레이놀즈 수와 영역을 판정한다.
  - 마찰 계수: 층류는 64/Re, 난류는 Colebrook를 반복 풀이하고 Haaland와 대조한다.
  - 국부 손실 계수 합 K를 더해 압력 손실을 낸다. 층류에서는 Hagen–Poiseuille 식과 직접 대조한다.
  - 천이 영역(Re 2300–4000)은 마찰 계수가 불확실하므로 TRANSITIONAL로 표시하고 보수 값을 쓴다.
  - 관망은 구간별 결과를 직렬·병렬로 합친다. 그 합산 스크립트도 known-answer를 둔다.
- **무차원 수로 먼저 거른다**:
  - 마하 수 > 0.3이면 압축성을 무시할 수 없다.
  - 스토크스 수로 입자가 유선을 따르는지 본다.
  - 프루드 수는 자유 표면이 있을 때 본다.
  - 이 단계에서 CFD가 필요한지, 어떤 모델이 필요한지가 정해진다.
- **CFD(2차 확인)의 해 검증**:
  - 판정 지표(압력 손실, 최대 유속, 벽 전단)에 34절 GCI를 적용한다.
  - 잔차는 3자리 이상 떨어져야 하고, 감시 지표가 정체해야 하고, 질량 불균형은 0.1 % 미만이어야 한다(제안).
  - 벽 처리에 맞는 y+(벽 함수 30–300, 저레이놀즈 모델 약 1)를 확인한다.
  - 직관 구간의 결과는 1차 오라클과 33절 방식으로 대조한다. 이 대조가 맞지 않으면 다른 결과도 믿지 않는다.
- **모델 선택 주의**:
  - 박리·와류가 큰 흐름에 정상 RANS를 쓰면 압력 손실을 과소평가할 수 있다. 비정상 해석이나 실측으로 확인한다.
  - 2D 대칭 가정은 대칭이 실제로 성립할 때만 쓴다.
  - 입자 혼입 유동은 CFD 단독으로 판정하지 않는다(10절 DEM 앙상블, 투입 시험).
- **실측 보정**: 유량–압력 시험대(차압계, 유량계의 불확도 기록), 가시화. 실측과의 비교는 34절의 E = S − D와 u_val로 쓴다.
- **known-answer**: D 6 mm, L 0.5 m, Q 2×10⁻⁶ m³/s(물)에서 마찰 손실은 Hagen–Poiseuille 값 31.438 Pa와 같다. 매끈한 관 Re 10⁵에서 Colebrook는 Blasius 0.316 Re^−0.25(0.01777)와 2 % 안에서 같다. Re 3044는 TRANSITIONAL로 표시된다(`selftest.py`).

## 38. 파괴

- **판정**: 있을 수 있는 결함(제작 결함, 적층 사이 공극, 피로 균열)이 하중에서 불안정하게 자라지 않는가. 피로 균열이 임계 크기까지 자라는 데 걸리는 수명이 요구 수명보다 긴가.
- **1차 오라클**: `scripts/hvp_fatigue.py lefm`과 `paris`.
  - `lefm`: 응력확대계수 K_I = Y σ √(πa)와 K_IC 대비 여유, 임계 균열 길이 a_c = (K_IC / (Yσ))² / π.
  - LEFM 유효성: 평면 변형 조건 a, B ≥ 2.5 (K_IC/σ_y)²와 순단면 응력. 맞지 않으면 경고하고 탄소성 평가(J 적분, 파괴 평가 선도 FAD: BS 7910, API 579)로 보낸다.
  - `paris`: Paris 법칙 da/dN = C ΔK^m을 a₀에서 a_c까지 적분한 수명. 폐형식을 수치 적분과 대조한다.
- **입력의 출처**:
  - 초기 결함 크기 a₀는 검사 능력(검출 가능한 최소 결함)이나 공정 결함 실측에서 온다. 0으로 두지 않는다.
  - 형상 계수 Y는 핸드북(Tada, Murakami) 또는 FE에서 온다. 균열 길이에 따라 Y가 바뀌면 Y(a)로 적분한다. 1차 오라클은 상수 Y이므로 보수적인 Y를 쓰고 그 사실을 `assumptions`에 적는다.
  - K_IC, C, m은 같은 재료·환경·두께의 시험값이어야 한다.
- **2차 확인**: FE J 적분이나 상호작용 적분으로 K를 구해 1차와 대조한다(33절). 균열 경로가 미리 정해지지 않으면 XFEM, 응집 영역 모델(견인–분리 법칙은 DCB·ENF 시험으로 보정), 상장(phase-field) 모델을 쓴다. 이것들은 보정 없이 판정에 쓰지 않는다.
- **3D 출력·폴리머 부품**:
  - 층간 박리가 주된 파괴 모드인 경우가 많다. 층간 파괴 인성(모드 I DCB, 모드 II ENF)을 출력 조건별로 잰다.
  - 노치 민감도와 충격(샤르피·아이조드)도 같은 방식으로 다룬다.
- **실측 보정**: 균열 성장 시험, 파면 관찰, 비파괴 검사(CT, 초음파)로 a₀를 정한다.
- **known-answer**: 중앙 균열 무한 평판(Y = 1), σ 100 MPa, a 0.01 m에서 K = 17.7245 MPa√m이다. Paris 수명 폐형식이 손 공식과 수치 적분과 같아야 한다. 평면 변형 크기 조건 미충족은 경고된다(`selftest.py`).

## 39. 진동·모달

- **판정**: 고유진동수가 가진 주파수(모터 회전수와 그 배수, 기어 맞물림, 펌프 맥동, 운송 진동)와 충분히 떨어져 있는가. 공진에서 진폭이나 응력이 한계를 넘지 않는가.
- **1차 오라클**: 집중 질량–스프링 모델, 보 이론. 외팔보 1차 진동수는 f₁ = (1.875² / 2π) √(EI / (m L⁴))이고, 여기서 m은 단위 길이 질량이다.
- **합격 기준 예**: 운전 범위의 가진 주파수와 고유진동수가 ±20 % 이상 떨어져 있어야 한다(제안). 피할 수 없으면 강제 진동 응답 응력을 36절 피로로 넘긴다.
- **2차 확인**: FE 모달 해석(34절 GCI를 고유진동수에 적용), 다체 동역학의 주파수 응답.
- **실측 보정**: 충격 망치 시험, 가속도계 측정. 실측 진동수로 경계 강성(체결부, 지지)을 보정한다. 경계 조건이 고유진동수 오차의 가장 흔한 원인이다.
- **known-answer**: 외팔보 공식 값과 FE 1차 모드가 메시 수렴 후 1 % 안에서 같아야 한다.

## 40. 크리프와 온도 의존(폴리머)

- **판정**: 지속 하중과 온도에서 변형(크리프)과 예하중 손실(응력 이완)이 수명 동안 한계 안에 있는가.
- **언제 필요한가**: 열가소성 수지 부품, 출력 부품의 볼트 체결부, 유리 전이 온도 근처에서 쓰는 부품(PLA는 약 55–60 °C, PETG는 약 80 °C — 재료 데이터로 확인), 히터나 모터 근처 부품.
- **1차 오라클**: 등시 응력–변형률 곡선이나 크리프 탄성률(시간·온도별)로 탄성 계산을 다시 한다. 온도 범위는 15절 열회로 결과에서 가져온다.
- **합격 기준 예**: 사용 수명 끝의 변형이 기능 공차 안이어야 하고, 체결 예하중이 최소 요구값 이상 남아야 한다(제안).
- **실측 보정**: 사용 온도에서의 크리프 쿠폰 시험, 체결부 토크 유지 시험.
- **주의**: 상온 단기 물성으로 계산한 강도·강성 PASS는 장기 하중과 고온에서 성립하지 않을 수 있다. 증거의 `limitations`에 "크리프 미검토"를 적는다.

## 41. 데이터 계층: 기록 → Parquet → SQL 판정 → MCP

- **목적**: 시뮬레이터 앙상블(10절), 관절 노력(11절), 피로 하중 이력(36절), 제어 로그(16·17절), 시험대 실측(9c)처럼 판정의 근거가 시계열일 때, 그 데이터를 남기고, 묻고, 인용하는 방법이다. 로봇 데이터 플랫폼(예: Alloy)의 구조, 즉 기록 → 열 저장 → 질의 → 에이전트 접근을 따르되, 판정 권한과 재현성은 이 skill의 규칙을 따른다.
- **배치**(`data/`, 저장소 기준 경로):

  | 경로 | 내용 | git |
  | --- | --- | --- |
  | `raw/<run>.mcap` | 원본 기록. 시뮬레이터, 시험대, 로봇 | 넣지 않음(LFS나 외부 저장). 해시는 `runs/`에 남음 |
  | `tables/<topic>/run_id=<run>/part.parquet` | 주제별 표. 열은 `t`(실행 시작부터 초), `log_time_ns`, 메시지 필드 | 크기에 따라. 넣지 않으면 재실행에 `--inputs`가 필요 |
  | `runs/<run>.json` | 실행 메타: 원본 경로와 해시, MCAP `hvp.run` 메타데이터(시나리오, 시드, 설계 커밋, 도구 버전), 주제별 행 수, 건너뛴 채널과 이유 | 넣음 |
  | `manifest.json` | 표와 실행 메타 전부의 sha256, 지문 | 넣음 |

- **실행 메타는 기록 안에 넣는다**: 시뮬레이터나 시험대가 MCAP를 쓸 때 `hvp.run` 메타데이터에 시나리오, 시드, 설계 커밋, 입력 해시, 도구 버전을 적는다. 그래야 데이터가 어느 설계의 것인지 판정 증거까지 이어진다.
- **판정은 저장된 질의가 낸다**(`hvp_query.py`). 검사 정의 파일(`checks/*.json`)은 두 종류다.
  - `metric`: SQL 결과 행에서 지표를 집계(max/min/mean)하고, 그 값이 나온 행(실행, 시각)을 `data.where`에 남긴다.
  - `events`: 조건이 이어지는 최대 구간을 실행별로 찾고, 최소 지속시간 규칙을 적용해 사건 수를 지표로 낸다. 지속시간은 구간 안 첫 표본과 마지막 표본의 시간차로, 물리적 지속시간보다 표본 간격 하나만큼 짧다. 규칙을 정할 때 이것을 반영한다.
  - 증거에는 SQL 원문, DuckDB 버전, 읽은 Parquet 파일과 검사 정의의 해시(`inputs`), 결과 행, 재실행 명령이 들어간다. 데이터가 바뀌면 `hvp_stale.py`가 그 증거를 STALE로 잡고, `hvp_cite.py --rerun`이 값을 다시 만들어 대조한다.
- **MCP는 묻는 창구이지 판정자가 아니다**(`hvp_mcp.py`).
  - 표를 메모리로 복사한 뒤 외부 접근을 끄고 설정을 잠근다. 단일 SELECT/WITH만 받고 결과 행 수를 제한한다.
  - 모든 답에 SQL, 데이터 지문, DuckDB 버전, 터미널 재실행 명령이 붙는다. 구간 조회는 솎아 낸 경우 그 사실을 함께 돌려준다.
  - MCP 답을 판정으로 쓰지 않는다. 판정이 필요하면 그 질의를 검사 정의로 저장해 `hvp_query.py`로 증거를 만든다.
  - 자연어로 패턴을 찾는 요청도 같다. 에이전트는 패턴을 `events` 정의로 **제안**하고, 사용자가 정의를 확인한 뒤 전체 이력에 돌린다.
- **원본은 사용자가 직접 본다**: 판단 자료는 데이터 기반 지표마다 값이 나온 실행과 시각을 보여 준다. 사용자는 그 MCAP를 Foxglove 같은 뷰어로 그 시각에 열어 원본을 확인한다.
- **정렬과 단위**: 시뮬레이션과 실측을 비교하려면 시간 기준(이벤트 동기, 공통 트리거), 표본 주기, 단위를 먼저 정해 실행 메타에 적는다. 정렬하지 않은 두 시계열의 차이는 판정 근거가 아니다.
- **환경**: 표준 라이브러리 도구와 달리 고정 패키지가 필요하다. `env/requirements-data.lock` 하나로 고정하고, Nix 프로젝트는 `env/flake.nix` 셸, 그 밖에는 저장소 밖 공유 venv를 쓴다(runbook 12절).
- **known-answer**: `scripts/selftest_data.py`. 합성 MCAP 세 실행으로 확인한다.
  - r2에 2.5 A 최고점을 1.040 s에 둔 80 ms 스파이크가 있다. 지표 검사는 r2·1.040 s·2.5 A·FAIL을 내야 한다.
  - r3의 20 ms 스파이크는 50 ms 규칙에서는 빠지고 10 ms 규칙에서는 잡혀야 한다.
  - 같은 기록을 다시 넣으면 Parquet가 바이트 단위로 같아야 한다.
  - 기록이 바뀌면 증거가 STALE이 되어야 한다.
  - MCP는 쓰기와 파일 읽기를 거부해야 한다.

## 42. 지속 결함 진단: 여러 번 고쳐도 남는 간섭·잠김

- **목적**: 수정 루프(SKILL 7)를 여러 번 돌았는데도 같은 간섭이나 잠김이 남을 때, 다음 수정 전에 원인을 판정하는 방법이다. 이런 결함은 대개 다섯 가지 중 하나다. 아래 각 항목은 그중 하나를 가려낸다.
  1. 원인이 하나가 아니다. 하나를 고치는 동안 다른 원인이 실패를 계속 만든다.
  2. 원인이 접촉이 아니다. 과구속, 관절 한계, 구동 설정, 입력 정의가 원인이다.
  3. 한 부품을 두 기구가 함께 안내한다. 경로가 어긋나 어디를 깎아도 접촉이 옮겨 간다.
  4. 검사기나 형상이 매번 다르다. 세대 혼재, 도구마다 다른 형상, 검사기 변경이 원인이다.
  5. 시도의 기록이 세션을 넘지 못한다. 같은 시도가 되풀이된다.
- **로봇 데이터 플랫폼에서 가져온 것**: 장애 분석 도구(예: Alloy)의 방법 가운데 시뮬레이션이 아니라 운영에 관한 네 가지를 설계 검증에 옮겼다.
  - 새 질문을 과거 전체 기록에 다시 돌리고, 해결 표시가 붙은 기록으로 해결 여부를 확인한다(시나리오).
  - 원인 분석을 배제됨, 확인 안 됨, 다음 시험으로 나눠 보고한다.
  - 지난 사례를 기억으로 남긴다.
  - 새 방법은 이미 해결한 사례에서 먼저 맞히는지 본다.
- **진입**: `hvp_fixloop.py open`이 PRIOR를 찾으면 PERSISTENT다. 같은 이슈 id나 겹치는 검사를 다룬 이전 루프를 이 클론의 모든 세션 원장과 `verification/fixlog/*.json`에서 찾는다. PERSISTENT 이슈는 확인된 가설이 있는 원인 원장(`--rca`)이 연결되기 전까지 `check`가 STOP을 낸다.

**42.1 원인 원장(`hvp_rca.py`)**

- 가설마다 적는 것: 주장, 시험, 맞을 때 결과(if_true), 아닐 때 결과(if_false), 비용, 상태, 근거 인용(`ev:`).
- 상태는 confirmed, ruled_out, not_confirmed, untested 넷이다.
  - confirmed는 if_true가 관찰되고, 그 가설에서 나온 수정이 예상대로 움직였을 때만 쓴다.
  - not_confirmed는 시험을 돌렸지만 결정하지 못한 경우다. 표본 부족이나 솔버 잡음이 예다. ruled_out과 섞지 않는다.
- 수정 시도는 기댄 가설을 함께 적는다. 확인되지 않은 가설에 기댄 시도(FIX_WITHOUT_CAUSE)가 반복 실패의 가장 흔한 형태다.
- 결과가 기록된 지난 시도가 확인되지 않거나 배제된 가설에 기댔으면 PAST로 표시한다. 원장의 결함이 아니라 결함이 되돌아온 이유의 기록이다. 결과가 없는 시도(계획 중이거나 진행 중)는 같은 경우 PROBLEM이고, 진행하지 않는다.
- 저장소에 둔다(`verification/rca/<이슈>.json`). 세션, 기계, 클론이 바뀌어도 남는다. `report --md`가 사용자에게 내는 표다(템플릿 1e).

**42.2 이력 재측정(`hvp_history.py`)**

- 같은 검사를 지난 커밋마다 임시 worktree에서 돌린다. `--paths`로 관련 파일을 바꾼 커밋만 고르고, `--grep`으로 이슈 id가 들어간 커밋만 고른다.
- `--overlay`로 오늘의 검사기를 옛 설계에 덮어 돌린다. 덮지 않으면 커밋마다 그때의 검사기가 판정하므로, 검사기 변화와 설계 변화가 섞인다. 두 번 돌려 비교하면 검사기 쪽 변화가 따로 보인다.
- 찾는 것:

  | 결과 | 뜻 |
  | --- | --- |
  | REGRESSED_AT | 처음 나빠진 커밋. 원인 커밋 후보 |
  | NEVER_PASSED | 범위 첫 커밋부터 실패. 결함이 더 오래됐다 |
  | CLAIM_NOT_SUPPORTED | 메시지는 수정을 주장하나 수치가 나아지지 않았다 |
  | CLAIM_STILL_FAILING | 수정을 주장한 커밋에서도 검사가 통과하지 않는다. 나아졌어도 해결은 아니다 |
  | STUCK | 최근 수정 주장들이 수치를 움직이지 못했다 |
  | NOT_RUN | 그 커밋에서 검사를 돌릴 수 없었다. 판정에서 빠진다 |

- 이력 재측정은 진단이지 판정이 아니다. 결과 파일에 status가 없다.

**42.3 해결된 사례로 방법 확인**

- 미해결 이슈에 쓰기 전에, 같은 종류의 이미 해결한 이슈에 같은 방법을 돌린다. 예: 수정 직전 커밋에서 `hvp_isolate.py --known <그때 확인된 쌍>`.
- MATCHES_KNOWN이 나와야 그 방법을 믿는다. 이것은 25절 known-answer 원칙을 진단 방법에 적용한 것이다.
- 해결 사례가 없으면 합성 사례로 대신한다. 예: 일부러 간격을 0으로 만든 쌍 하나.

**42.4 분리: 무엇이 막는가(`hvp_isolate.py`)**

- 항목은 끌 수 있는 것이다. 접촉쌍, 바디, 관절, 형상 특징, 파라미터 재정의가 예다.
- 명령은 항목 목록 파일을 받아, 실패가 없으면 0, 있으면 0이 아닌 값을 낸다. `--expect`로 실패 문구를 지정하면 다른 이유의 비정상 종료(파일 없음, 솔버 오류)는 UNRESOLVED로 빠진다.
- 대조군을 먼저 돈다.
  - 전부 켬: 실패해야 한다. 아니면 NOT_REPRODUCED.
  - 전부 끔: 통과해야 한다. 아니면 FAILS_WITHOUT_ITEMS다. 이때 원인은 목록 밖에 있다. 3절 이동도 계산으로 과구속과 잠김을 보고, 관절 한계, 구동 설정, 입력 부호와 단위를 본다.
  - 각 대조군을 반복해 결과가 다르면 FLAKY다. 결정론부터 고친다(26절).
- ddmin(Zeller & Hildebrandt, 2002)이 1-최소 실패 집합을 찾는다. 그 집합이 다시 실패하는지, 하나씩 빼면 통과하는지는 새 실행으로 확인한다. 항목 n개에 원인 하나면 실행 수는 대략 2·log₂n에 대조군과 재확인을 더한 만큼이다.
- `--all-causes`는 찾은 집합을 빼고 나머지가 여전히 실패하면 다음 원인을 찾는다. 원인이 둘 이상이면 하나씩 고치는 동안 실패가 남는다. 함께 묶어 한 이슈로 고친다.
- Fusion처럼 비싼 도구의 접촉 설정을 항목으로 쓸 때는 실행 수를 먼저 추정한다. 헤드리스 대리 검사(최소 거리 검사)로 줄일 수 있으면 그쪽에서 분리하고, 비싼 도구로는 결론만 확인한다.

**42.5 행정을 따른 접촉 지도(`hvp_contact.py`)**

- 입력: 쌍별·입력 위치별 부호 있는 최소 거리. 음수는 관통 깊이다. 6절 최소 거리 계산의 출력을 그대로 쓴다.
- `map`이 내는 것:
  - 쌍별 접촉 구간(시작, 끝, 최악 깊이와 위치)
  - 처음 닿는 입력 위치(FIRST). 잠김을 처음 만나는 순간이다
  - 표본 하나에서만 보인 구간(SINGLE_SAMPLE). 실제 범위를 모르므로 그 주변을 세분한다(6절)
- 의도 접촉(핀–홈, 기어 맞물림)은 이유와 함께 `--intended`에 두고 따로 보고한다(7절).
- `diff`는 이전 시도와 비교한다.

  | 분류 | 뜻 |
  | --- | --- |
  | RESOLVED | 접촉이 사라졌다 |
  | NEW | 없던 접촉이 생겼다 |
  | MOVED | 같은 쌍이 행정의 다른 위치로 옮겨 갔다 |
  | PERSISTS | 같은 위치, 깊이 변화가 허용치 안이다 |
  | IMPROVED, WORSENED | 같은 위치, 깊이가 허용치보다 크게 바뀌었다 |

- 사라진 쌍과 새로 생기거나 옮겨 간 쌍이 함께 있으면 WHACK_A_MOLE이다. 그 수정은 원인을 없애지 않고 접촉을 옮겼다. 다음 시도 전에 42.6과 3절을 본다.

**42.6 이중 안내 경로 적합(`hvp_pathfit.py`)**

- 대상: 홈·슬롯 안 핀, 캠 종동절, 트랙 안 슬라이더. 하나의 종동 요소를 두 기구가 함께 안내하는 경우다. 예: 손잡이 직선 이동과 Z자 홈.
- 방법:
  1. 홈 구속을 뺀 나머지 기구로 핀 중심 경로를 구한다. 3절 해석기를 쓰거나, CAD에서 슬롯 관절을 억제하고 입력을 움직여 핀 중심을 기록한다.
  2. 이 경로를 홈 중심선(폴리라인)과 비교한다.
  3. 허용 편차는 a = (홈 폭 − 핀 지름)/2 − 공차다.
- 결과와 다음 행동:

  | 결과 | 뜻 | 다음 행동 |
  | --- | --- | --- |
  | FITS | 전 행정에서 편차 ≤ a | 다른 원인(42.4)을 본다 |
  | OFFSET | 홈을 한 번 평행 이동(계산된 벡터)하면 전부 들어온다 | 배치나 형상 세대(1절)를 고친다 |
  | OVERTRAVEL | 행정 끝이 홈 끝을 넘는다 | 홈을 늘리거나 홈 안쪽에 멈춤을 둔다 |
  | LOCAL | 내부 모서리 근처, 행정의 15 % 미만 | 그 모서리만 경로에 맞게 둥글리거나 도피시킨다 |
  | MISMATCH | 모양이 다르다 | 홈을 경로에서 다시 만들거나(`--write-guide`), 두 구속 중 하나를 없앤다 |

- MISMATCH에서 홈을 넓히는 것은 선택지 하나일 뿐이다. 도구가 그 폭(핀 지름 + 2(최대 편차 + 공차))도 함께 보여 준다. 대신 다른 모든 위치에서 유격이 생기므로, 위치 정밀도와 맞바꾸는 결정은 사용자가 한다.
- 한계: 홈 평면 2D다. 면 밖 오차와 핀 기울기는 보지 못한다. 경로의 정확도는 그 경로를 만든 해석기나 CAD를 넘지 못한다.

**42.7 검사기·형상 일치**

- 두 도구의 결론이 다르면 먼저 같은 형상을 보고 있는지 확인한다. 예: 헤드리스 최소 거리는 여유가 있다고 하고, Fusion 접촉은 잠긴다고 하는 경우다.
- 경계마다 해시와 핵심 치수 하나를 남긴다. 경계는 계약 → 빌더 → STEP → Fusion 문서 순이다. 처음 어긋나는 경계를 찾는다(SKILL 7.2).
- 같은 형상인데도 결론이 다르면 33절 합의 검사의 DISAGREE와 같다. 어느 도구의 모델(접촉 강성, 허용 관통, 메시 해상도)이 틀렸는지를 독립 사례로 가린다. 편한 쪽을 고르지 않는다.
