# 산출물 템플릿

문서 한 개에 아래 순서로 둔다. 각 절 첫 문장은 그 절의 결론(숫자 포함)이다. 사용자가 정하지 않은 기준값은 "(제안)" 또는 "사용자 결정"으로 표시한다.

## 1. 요약

```
<진단 한 문단: 어디서 막혔고 왜 막혔는지, 기록된 실패 수치 포함>

기준 커밋: <프로젝트> <hash>(<브랜치>, <날짜>), ...

1. **<제안 1 — 싼 오라클이 비싼 도구를 문지기>**
2. **<제안 2 — 시뮬레이터에는 답할 수 있는 질문만>**
3. **<제안 3 — 실측 보정이 VALIDATED의 유일한 경로>**

범위: <다루지 않는 하위 시스템과 이유, 한 번만>
```

## 1a. 범위표 (모든 모드)

| 하위 시스템 | 주요 경로 | 범위 | 다루는 방식 |
| --- | --- | --- | --- |
| <이름> | `<경로>` | 포함 | 전체 |
| <이름> | `<경로>` | 제외 | keep-out 영역(치수 상자·질량·고정 위치)만, 이유 한 줄 |

## 1b. 실행 기록과 재현성 관찰 (실행·보고 모드)

```
실행 대상: <commit>(<브랜치>), 작업 트리 해시 <sha256 앞 12자>, worktree <경로 또는 "공유 체크아웃">
동시 세션: <없음 / 있음 — 근거>
HEAD 타임라인: <시작 HEAD> → <종료 HEAD>, 실행 중 입력 변경 <예/아니오>
```

| 단계 | 명령 | 소요 | 도구 버전 | 증거 경로 | 판정(증거 status) | 재현 여부 |
| --- | --- | --- | --- | --- | --- | --- |
| L0 감사 | `python3 source/<...>.py` | 0.04 s | Python 3.x | `verification/runs/<commit>/<시각>/...` | <status> | 휘발성 필드만 변경 / 값 변경 |

- **NOT_RUN**: <단계와 이유: 원격 GUI 필요, 제외 범위, 하드웨어 없음>
- **재계산 대조**: <문서 수치 중 독립 재계산한 항목과 일치 여부>
- **정본 갱신**: <갱신하지 않음 / 갱신한 파일과 이유>

## 1c. 수정 보고 (수정 모드)

```
### <대상> 수정 — <날짜>

**원인**: <부품·쌍·자세, 수치(관통 깊이, 겹침 체적, 실제 단면·면적)>
**수정**: <바꾼 빌더·파라미터·검사기, 파일 경로>
**검사기 정정**: <있으면: 무엇이 틀렸고 어떻게 고쳤는지>
**재실행**: <영향받은 게이트 목록과 전후 status·수치>
**정정한 이전 주장**: <이전 수치 → 새 수치>
**남은 한계**: <NOT_RUN, 형상 한계, 실측 필요 항목>
**커밋**: <hash>, 포함 경로 <목록>(동시 세션 파일 제외)
```

## 9. 에이전트 운영 규칙, 실행 순서, 사용자 결정 체크리스트

- 운영 규칙: SKILL.md 6절의 7개 규칙을 프로젝트 고유 이름(브랜치, 리뷰어, 실행 머신)으로 바꿔 넣는다.
- 실행 순서: 지금 막힌 지점을 직접 푸는 CPU 오라클 → 제어 전수 → 연속·계약 → 시뮬레이터 개정 → 실측 → 원격 확인.
- 체크리스트: `- [ ]` 항목으로 사용자 결정이 필요한 기준값과 분기(작업 브랜치, 해소 방향, 계약 개정 제출 여부).
