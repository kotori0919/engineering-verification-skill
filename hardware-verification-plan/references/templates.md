# 산출물 템플릿

문서 한 개에 아래 순서로 둔다. 모드별로 필요한 절만 쓴다(SKILL.md "산출물"). 각 절 첫 문장은 그 절의 결론(숫자 포함)이다. 사용자가 정하지 않은 기준값은 "(제안)" 또는 "사용자 결정"으로 표시한다.

## 1. 요약

```
<진단 한 문단: 세 목표(물리적 타당성, 조립 가능성, 의도 동작) 각각의 근거 상태, 어디서 막혔고 왜인지, 기록된 수치 포함>

기준 커밋: <프로젝트> <hash>(<브랜치>, <날짜>)
판정 집계: PASS <n>, PASS_BELOW_TARGET <n>, PASS_BY_MODEL_CHANGE <n>, FAIL <n>, BLOCKED <n>, NOT_RUN <n>
미결 공칭–실측 불일치: <n>건(영향 판정 <m>건)

1. **<제안 1>**

범위: <다루지 않는 하위 시스템과 이유, 한 번만>
```

## 9. 에이전트 운영 규칙, 실행 순서, 사용자 결정 체크리스트

- 운영 규칙: SKILL.md 10단계의 규칙을 프로젝트 고유 이름(브랜치, 리뷰어, 실행 머신, 훅·스위트 이름)으로 바꿔 넣는다.
- 실행 순서: 검사기 known-answer → 지금 막힌 지점을 직접 푸는 CPU 오라클 → 제어 전수 → 연속·계약 → 시뮬레이터 개정 → 실측 → 원격 확인.
- 체크리스트: `- [ ]` 항목으로 사용자 결정이 필요한 기준값(하한·목표), PASS_BELOW_TARGET 수용 여부, PASS_BY_MODEL_CHANGE 확인 방법, 미결 불일치의 처리, 구매·가공·통전 승인.

## 9c. 측정 기록 양식

측정값은 저장소의 기록 JSON(`<경로>/measurements/<부품>.json`)에 넣고, 그 파일을 입력으로 쓰는 판정을 다시 돌린다.

```json
{
  "item": "FAI-1",
  "part": "<부품>",
  "part_serial": "<일련번호>",
  "cad_solid_sha256": "<해시>",
  "nominal_mm": 0.0,
  "tolerance_mm": [-0.0, 0.0],
  "gauge": {"id": "<게이지>", "grr_percent": null, "calibrated": "<날짜>"},
  "readings_mm": [],
  "measured_by": "<이름>",
  "measured_at": "<UTC 시각>",
  "status": "MEASURED",
  "rejudge": ["<다시 돌릴 판정 명령 또는 gate ID>"]
}
```

- `grr_percent`가 null이면 공차 판정은 "판정 불가"다.
- 공칭과 다른 측정값은 7a 불일치 대장에도 올린다.
